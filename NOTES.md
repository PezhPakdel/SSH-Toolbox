# Decisions and open items

Decisions the builder made on its own, and anything blocked. Newest last.

- 1.8: Dividers and tab reordering use pointer events, not HTML drag and drop, because Tauri's file-drop handling (needed in 3.5) switches HTML drag and drop off on Windows.
- 1.8: A new split pane runs the same kind of session as the pane it came from.
- 1.9: Hidden tabs stay mounted (display: none), so their terminals keep running. Closing a tab closes its sessions.
- 1.10: Shortcuts are caught in the capture phase on `window`, so they never reach the program. Search (Ctrl+Shift+F) and type-into-all-panes (Ctrl+Shift+B) are wired in tasks 1.13 and 1.15.
- Until the shell menu (1.11), "new tab" opens the first shell in the list.
- 1.12: Settings changes (font, size, theme, scrollback) apply to open terminals at once. The renderer applies to terminals opened afterwards. The light theme changes the terminal only; the tab bar and dialogs stay dark.
- 1.12: A `settings.toml` that can't be read is moved to `settings.toml.bad` and defaults are used, so the user's text is kept. Out-of-range numbers in a hand-edited file are pulled into range.
- 1.13: Links go through the backend command open_link, which checks http/https with the url crate before calling tauri-plugin-opener from Rust. The plugin itself is not registered with the window, so the interface has no permission to it.
- 1.14: The layout is saved 0.5 s after any change and read once at start, only if `restore_layout` is on. A layout that can't be read or fails the checks is moved to `layout.toml.bad`. Restored panes open new sessions of the saved kind.
- 1.15: Type-into-all-panes (P5) is done: Ctrl+Shift+B, with a red banner in the tab bar while it is on. It sends to the other panes of the same tab only.
- 1.15: T9 (save session output) is left for later: saving needs a file-save dialog, and the dialog plugin isn't in the approved list. P7 (move a tab to its own window) is left for later too.
- 1.16: Measured on the owner's Windows PC with a release build (`npx tauri build --no-bundle`), one PowerShell tab: memory 150 MB (Q2, target 250), usable after 1.3 s on a first launch (Q3, target 2 s), program file 10 MB (Q1 counts the installer, measured in 6.2). Linux numbers come from the owner.
- 2.1: `sessions.toml` has no field that can hold a secret, and unknown keys in a hand-edited file are dropped on the next save. A file that can't be read is never overwritten: saving is refused until the user chooses "start again", which keeps the old file as `sessions.toml.bad`. Every save keeps the previous version as `<name>.bak` (this also applies to settings and layout).
- 2.2: There is deliberately no command that sends a saved secret to the interface. Only the backend reads secrets, when connecting. The Linux keychain code compiles in CI but is untested until the owner tries it on Ubuntu.
- 2.3: The host key rules are tested end to end against a small SSH server that runs inside the test (`ssh/testing.rs`), so no container is needed. Its two keys are throwaway keys made for the tests and open nothing. A key read from a private key file carries a comment that a server's key doesn't, so tests strip it before comparing.
- 2.3: Prompts reach the interface as a `prompt` status and are answered with the `prompt_respond` command. The prompt dialogs themselves are built with the SSH pane in 2.5.
- 2.4: Login tests run against the in-process server. The Windows agent test uses this PC's real `ssh-agent` if it is running and holds a key, and passes without doing anything otherwise. The Linux agent path (`SSH_AUTH_SOCK`) is checked by CI's `check_ssh` example only.
- 2.5: An SSH pane's session exists at once and connects in the background, so closing the pane while a question is open cancels it cleanly. Text typed before the shell opens is dropped. A connection that is lost shows `connection_lost` only in the panes on it, and Reconnect opens a fresh session (a dead connection is never reused). The server in the tests can be "crashed" by cutting its socket, so these cases run without a container.
- 2.5: Prompt dialogs (host key, new key type in warning colours with Cancel as the default, password, passphrase) show over the terminal.
- 2.6: The sidebar (☰ button) lists saved sessions in folders with search, an editor for SSH sessions, and delete with confirmation (a deleted session's saved secrets go with it, and a deleted folder's contents move up a level). Serial and FTP sessions appear in the list but can't be opened or edited until phases 3 and 4. The sidebar was checked in the real app (create, search, validation, delete); connecting to a real server has not been tried yet because Docker isn't running here.
- 2.7: A restored SSH pane shows its name and a Connect button; it doesn't connect until clicked. Splitting an SSH pane opens a new session straight away, as that is the user's own action.
- 2.8: New keys are made with `rand::rng()` (a CSPRNG seeded from the OS) in create-new mode, so an existing file is never touched, and a lone `.pub` also blocks a name. On Windows the private key gets the icacls pattern (owner, SYSTEM, administrators) and the file is deleted again if that fails; this was checked on this PC. The key screen that uses these commands arrives with the install flow in 2.9.
- 2.9/2.10: The Unix install script runs on a real `sh` in the tests (fresh user, existing file, no final line ending, twice) and the whole flow (password login, detect, install, separate key-only login) runs against the in-process server, which executes commands and honours `authorized_keys`. Those tests do nothing on a machine with no `sh`, so Linux CI is where they always run. The Windows script and its UTF-16 encoding are unit-tested as text only: running it would change this PC's `administrators_authorized_keys`, so real testing is on the owner's list.
- 2.9: The key dialog (🔑 on a session in the sidebar) can make a new key or pick one from `~/.ssh`. Afterwards it offers to switch the session to the key, and separately to delete the saved password. Nothing is deleted unless the user ticks it.
- 2.11: Jump hosts are tested with two in-process servers (the jump host forwards, and the target is reached only through it; closing the pane closes both connections). A jump host that refuses forwarding gives a failure that names the step ("step 2 of 2"). Up to 3 jump hosts; each logs in with its own saved method and has its host key checked.
- 2.11: Config import reads `Host`, `HostName`, `Port`, `User`, `IdentityFile`, `ProxyJump` and `Include` (one level). Settings in `Host *` blocks are not applied to other hosts (a simplification), `Match` blocks are skipped, and `IdentityFile` values with `%` tokens are dropped. A host with no key file imports as an SSH-agent session. The ⇩ button in the sidebar opens the import dialog; the user's file is only read.
- 2.12: Forwards (local, remote, SOCKS5 with no-auth and CONNECT only) are tested against the in-process server and a small echo server. A listener on anything but loopback needs the user to confirm a warning, enforced in the backend as well as shown in the dialog. A forward ends when its connection drops; forwards are not saved to disk and don't come back after a restart. Deleting a session stops its forwards. The ⇄ button on an SSH session opens the dialog.
- 2.13 security review (a separate reviewer that read the code cold; no critical findings). Fixed, each with a test where it can be tested:
  - The "host key changed" message gave the wrong line when the file had comment lines above the entry (the library skips comments when counting). It now counts physical lines and also gives the `ssh-keygen -R` command for that host.
  - Chains of two or more jump hosts went through the oldest connection instead of the newest. Fixed, with a two-hop test.
  - Terminal hyperlinks (OSC 8) bypassed the Ctrl+click and http/https-only rule. They now go through the same handler and the backend check.
  - `known_hosts` lines the library can't read but OpenSSH honours (tabs, wildcards, `@cert-authority`, `@revoked`) no longer make a pinned host look new: the connection stops with an explanation. Host names are compared without regard to case.
  - The 20 s connect timeout no longer runs while the user is looking at a host key question.
  - One slow question no longer freezes every other SSH pane: the connection lock is now per saved session.
  - The Windows key script adds a line break first if `administrators_authorized_keys` doesn't end with one.
  - New keys: the private key file is locked to the owner before the key is written, and a `.pub` file the call didn't create is never deleted.
  - Pasted text has control characters (including Escape) removed before the multi-line check.
  - Channels a server opens towards this computer (session, agent, X11, direct) are refused; only the remote forwards the user asked for are accepted.
  - Host names with `, [ ] " '` are refused when saving a session; a remote forward on a non-loopback address needs the same confirmation as the others.
  - Installing an existing key now works: its own comment (for example `me@laptop`) is replaced by `sshtoolbox`.
- UI: one design system in `src/lib/ui/theme.css` (colour variables for dark and light, buttons, forms, dialogs, menus) and `Icon.svelte` (line icons). The light theme now changes the whole window, not only the terminal. Tabs show the kind of session and have split buttons; the active pane is outlined when there are several; a welcome screen appears when every tab is closed; the sidebar has icons, a folder count, hover tools and an empty state; session errors appear as a banner with Reconnect. The default terminal font now uses Cascadia Mono / SF Mono / Consolas instead of the generic "monospace".
- `SSH_TOOLBOX_CONFIG_DIR` (environment variable) makes the app use another config folder, for trying things out or screenshots without touching the real saved sessions.
- 3.2: The queue writes to `<name>.sshtoolbox-part` and renames it when complete; if the target exists it asks (overwrite, skip, overwrite all, skip all). Replacing removes the old file just before the rename, because SFTP refuses to rename onto an existing file. A cancelled or failed transfer deletes only its own part file. Folder copies skip links and any name from the source that could escape the destination, and report them. Folder deletes list everything first (so the user can be told the count) and remove from the bottom up.
- 3.3: SFTP runs on a new channel of the existing connection (one login). The tests use an SFTP server built into the test code that serves a temporary folder and, like OpenSSH, refuses renames onto existing files. Real OpenSSH has not been tried; Docker isn't running here.
- 3.4: The Files button (folder icon, top right) opens a panel beside the terminal. It shows the active pane's server (SFTP, on the pane's own connection) or WSL distribution above, and this computer below. Each side can make folders, rename, delete (the confirmation counts files and folders), change permissions (servers) and transfer the selected rows with the Download / Upload buttons. Transfers are listed with progress and Cancel; an existing file brings up Replace / Skip / Replace all / Skip all.
- 3.5: Rows can be dragged from one list to the other, and files dragged in from the desktop onto the server list are uploaded to the folder shown. Dragging out to the desktop isn't possible with the web view's drag support, so that direction is left out (use Download). Both drags were written and the buttons were tested in the real app, but the drags themselves were not tried (no mouse): the owner should try them.
- 3.6: WSL files use the local backend on `\wsl.localhost\<distro>\`. Tried for real on this PC: uploading 300 KB into Ubuntu's /tmp worked, left no part file, and a second upload asked before replacing.
- 3.7/3.8: FTP and FTPS use `suppaftp` (passive mode; `MLSD`, falling back to `LIST`). Plain FTP asks every time before anything is sent, and a refusal sends nothing. FTPS checks the certificate against this computer's trusted authorities. If that fails, the user sees the reason, the subject, the expiry and the SHA-256 fingerprint, and the connection goes ahead only if they accept; the accepted fingerprint is saved as `trusted_cert_sha256` with the session and a different certificate later is asked about again (with the reason saying so). The check is a custom verifier that still runs the normal checks and the handshake signatures; it only adds "or exactly the certificate the user accepted". With implicit TLS the app sends `PBSZ 0` and `PROT P` itself so data connections are protected. The tests use an FTP and FTPS server built into the test code (21 tests); the `vsftpd` container from the task list was not used because Docker isn't running here, so a real server is still untried. An empty user name means an anonymous login. FTP sessions have no terminal: double-clicking one shows its files in the Files panel until another tab or pane is chosen. Permissions can't be changed over FTP.
- Added on request: reachability dots in the session list (a TCP connect to each server's port, at most 24 at once, 2.5 s each; sessions that go through a jump host are not checked). Settings: `reachability_enabled`, `reachability_interval_secs` (0 = only at start and when the list changes; otherwise 5 to 3600). The footer shows processor, memory, disk, load and uptime of the active SSH server (one short command on the existing connection, Linux servers only, never connects by itself) or of this computer for other tabs. Settings: `stats_enabled`, `stats_interval_secs` (2 to 300). The tab strip now sits above the terminals instead of across the whole window.
- 3.10: A terminal's folder is read from OSC 7 (`file://host/path`). The text is untrusted, so it is checked first (must be a `file://` address, percent escapes decoded, no control characters, at most 4096 characters; anything else is dropped), and the result only changes which folder the server list in the Files panel shows. It is never run, opened or sent anywhere. For WSL panes the path is turned into `\\wsl.localhost\<distro>\...`. The route button in the Files panel header switches following on and off (remembered). Many shells don't send OSC 7 by themselves (Ubuntu's bash does so only inside some terminal programs), so the panel stays where it is until the shell does: adding `PROMPT_COMMAND='printf "\033]7;file://%s%s\a" "$HOSTNAME" "$PWD"'` to `~/.bashrc` makes bash send it. Not tried in the real app (the owner's copy was open); the reading and cleaning of the value is unit-tested. Opening files in a local editor (F8) is left for later, as planned.
- Phase 4 (serial): one task owns each open port and does the reading, the writing and the control lines (DTR, RTS, break), so the port is never used from two places. The port is behind a small `Port` trait, so the tests use a stand-in made from a pipe (13 tests: output reaches the terminal, typed text gets the chosen line ending, local echo, DTR/RTS/break, unplugging gives a failed status, closing, a port that can't be opened). No `socat` was used and no real or virtual port was opened in tests: that needs the owner's device (task 4.6) or later work on Linux CI. A read error or end of stream is reported as "The device was unplugged, or stopped answering" and the pane offers Reconnect, as for SSH. A port that can't be opened gives the same kind of message instead of a crash. On Linux a permission error explains `sudo usermod -aG dialout $USER` followed by logging out and in; the app only shows the command. Ports are listed with USB names (cleaned of control characters, cut to 80 characters, since they come from the device); the editor takes a typed port too. Local echo moves to the next line on Enter and rubs out on backspace. The Enter key sends CR, LF or CR+LF as chosen. Serial panes restored from a saved layout wait for a click on Connect, like SSH panes (nothing opens a port by itself). DTR/RTS buttons show what was last set, not what the device reports.
- Security pass on the newer code (self-review): (1) FTP passive mode now ignores the address in the server's answer and uses the control connection's address, so a hostile server cannot make the app connect elsewhere (tested with a server that answers with another address). (2) The reachability check no longer takes addresses from the interface: the backend reads the saved sessions itself, so it cannot be used to try other hosts. Checked and fine: FTP names from servers go through the same escape checks as SFTP names; the FTPS pin still runs the normal signature checks; the footer runs one fixed command and parses its output defensively; device names and OSC 7 text are cleaned before use. - 5.1 (Docker over SSH): `docker::ssh::connect_ssh` gives a Docker client that sends every request over the session's existing SSH connection, one fresh channel per HTTP connection (so a log stream never blocks a list). Method 1 runs `docker system dial-stdio` on an exec channel; method 2 opens a channel to `/var/run/docker.sock`; the first that answers a ping wins. When neither works, the same command is run once to learn why, and only the kind of problem (permission, not installed, engine stopped, other) is turned into a fixed message: the server's own text is never shown. The permission message names the `docker` group and says the app never uses sudo. Tested here against an SSH server and a fake Docker engine that both run inside the test (7 tests); the real Docker proof is the new `check_docker_ssh` step in Linux CI, which needs the sshd container to have `docker-cli` and the host socket mounted (the entrypoint adds the test user to the socket's group). Not yet seen passing: Linux CI. Not covered yet: attach/exec (needs an HTTP upgrade, task 5.6).

## X11 forwarding (2026-11-03)
- Sessions have an `x11` option (off by default, old files load fine). When on, the SSH pane asks the server for X11 forwarding with a made-up cookie (new per connection). Programs that open windows connect back through the tunnel; we check they bring that cookie and swap in the real one for the local X server (`crates/core/src/x11/`). The real cookie never leaves this PC. A program with the wrong cookie is dropped before it reaches the local server.
- Ubuntu: uses the desktop's `$DISPLAY` and the cookie in `~/.Xauthority`. Windows: the app uses VcXsrv. Order: its own running server; else something already listening on port 6000 (the user's own X server, used without a cookie); else it starts VcXsrv (found next to the app in `x-server\`, or in Program Files) in `-multiwindow -clipboard -wgl` mode with `-auth` pointing at a cookie file in the config folder, so only our programs get in. Never uses `-ac`.
- If forwarding can't be set up the shell still opens and the terminal prints a bracketed line saying why (no X server, or the server refused it).
- Tools, X server shows the state and has Start/Stop. The server is stopped when the app quits.
- Decision: VcXsrv is not bundled yet (GPL: needs the source offer shipped with the installer). Decide after the owner has tried it.
- Tested with a fake SSH server and a fake local X server (cookie swap, wrong cookie, refusing server, option off). NOT tested against a real VcXsrv, a real sshd, or Ubuntu: the owner needs VcXsrv installed to try it.

## Edit server files on this computer (2026-11-03)
- Double-click a file in the server's list (or right-click, Open and edit here / Open with…): `crates/core/src/files/edit.rs` downloads it into `%TEMP%\ssh-toolbox-edit\<id>\<name>` (a private folder on Linux, mode 0700), opens it in the program the system uses (`open.rs`: explorer.exe / xdg-open / open), and watches the copy by looking at its size and time every 0.6 s. A save is reported once the file has stopped changing. Works for SFTP, FTP and WSL files, since it uses the common file backend.
- The page decides what happens (`src/lib/files/edits.svelte.ts`): ask each time (default) or send automatically. The choice is remembered in localStorage (`edit-upload-mode`), set by "Always send automatically" in the question or the checkbox in the "Editing here" list in the file panel. The question shows anywhere in the app (`EditPrompt.svelte`).
- Safety: before sending, the server's file time is compared with the one seen at download. If it changed, nothing is sent until the user agrees to replace it. Files over 50 MB are refused. Programs and scripts (exe, bat, ps1, js, lnk, desktop and similar, list in `is_risky_to_open`) are never opened with the default action: the system's "Open with" dialog is used on Windows, so a downloaded file can't run by itself. The local copy is deleted when the user stops editing, when the app quits, and at the next start if the app was killed.
- Decision: upload writes straight over the server file (no temporary name and rename), because SFTP rename over an existing file fails on many servers. A failed upload leaves the local copy and shows the error.
- Tested: watcher, conflict check and cleanup with a local folder as the "server"; the full download, edit, upload and conflict round trip over SFTP against the test server; the page logic with a fake backend. NOT tested: a real editor and a real SSH server (the owner's server), Linux/macOS opening.
